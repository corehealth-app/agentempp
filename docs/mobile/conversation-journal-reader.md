# Read-only conversation journal adapter

This implements the packet in `conversation-journal-api.md` behind the existing
default-off conversation capability. The Admin GET route and BFF re-export are
`/api/mobile/v1/conversation/journal`. Actual Auth and entitlement middleware run
before the reader; original owner and epoch headers are mandatory. Query keys
are limited to one `limit` and one `cursor`; limit defaults to ten and is 1–25.
There is no per-command hash header, POST handler or old-message fallback.

`createSupabaseConversationMealJournalStore(db).read(query)` is inert until called
and makes one `read_conversation_meal_journal_page` RPC. It validates the complete
closed private response, actual owner/epoch bindings, original command hash,
receipt dependencies, unique event IDs, descending server order and the last
returned cursor. A lost read has no local retry. It never looks up domain rows
directly or initializes a source/day/semantic attempt.

The new `parseConversationMealEditHistoricalReceipt(raw, binding)` export uses
the existing private receipt parser and validates the actual full original
binding plus application chronology. Historical rows have no operation body;
the reader never manufactures one or recomputes its edit-intent hash. Existing
operation-body parsers and their invariants remain unchanged.

`createConversationMealJournalService(db, ports).read(auth, request)` snapshots
auth, owner, request and callback ports before awaiting. Current profile
observations before and after the read bind the server epoch and stable clinical
binding. Changed profile/config/health revision, day, policy or epoch refuses the
whole page. Events admitted between those observations can be included; all
event, effect and terminal clocks must fit the final observation. Invalid typed
port results are revalidated before becoming public authority.

Saved entries use the existing historical-feedback presentation and saved-result
projectors. Optional presentation failures yield null feedback without repeating
an effect. Accepted feedback must match the outer current policy and observation
interval. Edits use the qualified private receipt and the existing sanitized
13-key public-effect projector. Private snapshot, before/after groups, historical
daily balance and clinical source bodies are never public entry fields.

The terminal receipt is a closed whitelist of the actual sealed decision. Its
opaque `decision_hash` is preserved rather than reconstructed in JavaScript.
The result and receipt have the same original command identity/reason/indexes.
It is evidence of delivery of a non-registration answer, not a saved-food ACK,
XP or a grant to rewrite/resubmit an intent. Pending and saved entries have null
terminal receipts; reading any page itself performs no acknowledgement.

Cursors are canonical base64url JSON with exact fields
`{v:1,owner_id,epoch,at,id}` in that serialized order. Alternate encodings, extra
or repeated JSON/query fields, foreign owners and old epochs are refused. The
SQL RPC remains authority for the actual owned anchor. Clients retain the opaque
cursor and server event order.

The data packet is capped at 240,000 UTF-8 bytes, including its continuation
cursor. Projection stops before the next whole entry and continues from the last
included event without skipping. An unrepresentable first entry fails with
`conversation_journal_entry_too_large`. Current strict entry bounds normally
keep an individual entry below that cap. No device-clock ordering or offset
pagination is introduced.

The synthetic standard-envelope fixture is
`apps/admin/src/lib/mobile-api/__fixtures__/conversation-journal-public.json`,
SHA256 `940b4f9aa15730e531cdbb9e7861602a0f3a96f2aa70ad6df31fa5208a6cc0ed`.
It is generated by the actual private decoder/public service and pinned by a
golden test, with distinct Auth/patient IDs and edit, terminal, pending and saved
entries. It is a transport fixture, not evidence of a persisted database effect.

Local focused checks cover closed SQL bindings, historical receipt invariants,
unknown read outcomes, current-policy drift/reset, callback/auth snapshots,
private-field rejection, cursor ties/continuation, the exact 240,000-byte edge,
UTF-8 byte overflow, optional feedback failure and route preconditions. Neighbor
edit/decision/command/feedback tests, non-incremental Admin types and scoped
Biome also pass. The implementation task performs no PG/cloud/provider calls,
no full Admin/native build and no activation. Parent integration, coherent BFF
surface/build checks, actual SDK/REST and native acceptance remain separate gates.
