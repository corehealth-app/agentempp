# Ordinary photo lineage in the conversational intake

This additive bridge keeps `conversation_photo` as its actual private-media
purpose. It does not retag an ordinary upload as `meal_photo`, `gym_photo` or a
clinical assessment. Capture controls and connected qualification are required
before enabling it for the distributed app.

The worker's closed `conversation.image-result.v1` remains the stored, immutable
processing result. Neutral capture, the routing claim, sealed selection and typed
child bind its actual owner, asset, clocks, epoch and processing hash. A routing
hint cannot override classification: meal/label observations belong to a meal
child, equipment to a workout child, and unsupported body/scale/other/unknown
images cannot mint either child. The router asks for an appropriate description
instead of invoking another model for unsupported pixels.

Shared readers extract the validated analysis without replacing the envelope in
the source or receipts. Original captions and media context remain separate. An
equipment picture is an observation; only an explicit performed report can
establish an activity, duration or calories through the existing workout rules.

A printed nutrition serving is not the quantity consumed. For a named label, the
existing missing-portion observation uses quantity estimate zero and preserves
the full label. That zero never represents a saved food or nutrient value. A
label without a usable product name receives a specific description question
before a typed child can be selected. The existing explicit label-consent and
missing-quantity gates remain; this bridge does not consent or confirm on the
person's behalf.

An ordinary meal image with no identified items can still carry a complete
literal caption or media context. The typed source retains those exact words and
the original image hash, without inventing a visual item. Without either literal
evidence or visible items, the router asks what was consumed. Empty legacy
`meal_photo` observations remain refused.

The migration pins seven exact current function bodies before narrow
replacements and adds two private immutable observation helpers with no execute
grants to public/client/service roles. It creates no tables, records, flags,
workers, provider requests or rewards. Older raw photo/audio and text behavior,
receipts, leases and authorization fences remain in their existing paths.

Qualification uses the actual local PostgreSQL capture/seal/source and durable
semantic validator, rolled back after each run. Cross-language samples retain
the genuine selected child; the public pending result is deliberately not a
fabricated saved receipt. iOS requires negotiated provenance and the original
asset/identity/hash before matching it. Native acceptance, upload/worker cleanup,
photo/audio registration, cold edit/undo/panel agreement, TestFlight and Roberto
acceptance remain separate gates. Do not describe distributed build 17 as having
camera or microphone support.
