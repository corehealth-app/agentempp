# Current-policy guard for historical command feedback

`createSupabaseConversationMealFeedbackPresentation(db, dependencies?)` exposes `readHistorical({ auth, command, receipt, serverBinding })`. This private read-only service guards immutable original feedback with actual current C11 observations. It does not create feedback, rewrite a receipt, recalculate a meal/day, initialize a day, grant writer authority, issue rewards, or activate a route/native reader.

`serverBinding` must be the real server journal/readPrepared binding, including the command's durable epoch, owner, command ID and input hash. It is never a mobile `expectedEpoch` or evidence manufactured from JSON shape. The authenticated owner, recomputed full command, mandatory factual effect receipt and closed server binding are validated and detached before I/O. The caller remains responsible for obtaining those server records through the authenticated command driver.

## Actual observation window

Defaults are the real `createSupabaseCurrentClinicalStateSource` and `createSupabaseConversationMealFeedbackService(...).readOriginal`. Producer callback identities are captured during inert construction. Every call performs:

1. Actual owned current profile capture with `expectedEpoch` from the server command, decoded by the existing current-state functions.
2. Immutable original receipt read only; no `ensureOriginal`, source recapture, seal or generic T2C path.
3. A second actual owned capture with the same expected epoch. Owner, epoch and the existing full stable clinical binding must agree. The second timestamp cannot predate the first, and the first cannot predate server admission.
4. Projection through the existing public-policy projector and synchronous presentation rendering.

The full binding includes body/config/generation/health state and provenance, not merely profile hash or selected public flags. Snapshot timestamps retain sub-millisecond ordering. Unknown policy, missing original, reset, owner/event/log/date gap, source failure or pre/post drift returns `null`, with no unsafe legacy fallback or private detail in errors/logs. This is a point-in-time read guard, not a durable clinical write capability; consumers must refresh rather than treat its provenance as perpetual permission.

## Separate wrapper

The result schema is `conversation.feedback-presentation.v1`, with `mode: historical`, `assistant: Flow AI`, original schema/registration/kind/local-date metadata, sanitized `current_policy`, and provenance containing server epoch, command ID and the final current `observed_at`. No raw body, health codes, generation authority, profile/context hashes or source observations are returned.

- V2: `status: available`, `format: sections`, original owned `recorded` meal facts/totals, and six rendered sections in the existing saved/items/summary/day/block/education order.
- Unrestricted v1: `status: available`, `format: legacy`, immutable `legacy_body` compatibility. The wrapper identifies it as historical.
- Restricted v1: `status: unavailable`, `format: placeholder`, neutral saved/unavailable text only. No opaque original lines, comment, incentive or legacy body are included.

The wrapper never returns a masked clone labeled as the original `registration.feedback.v2`. A private adapter can use the shared V2 parser/renderer, but only presentation sections and unchanged recorded meal facts leave that adapter. Stored original bytes remain untouched. Consumers must display the historical mode/date; these fields/sections are not Today or current progress panels.

## Current masks, historical numbers

The service uses the actual `readCurrentClinicalState` / `captureCurrentClinicalState` / `projectCurrentClinicalPublicPolicy` chain. There is no injection point for a policy-shaped object to become current authority. Food names, quantities, per-log nutrition and meal totals remain the original owned facts.

For V2, current pause masks old targets, percentages, food balance, objective and 7,700 progress. Individual hide flags mask their fields: calorie/protein target and percentage independently; balance separately; objective and block protect consolidated progress. Incomplete assessment withholds day/block/education guidance even when pause/hide flags are otherwise false. Hidden targets are not replaced with profile calculations. Revealed numbers are copied from the original receipt, without recomputation or reads of current Today/progress. Day/block text explicitly identifies the moment of registration; an old not-applicable block cannot claim anything about the user's current objective.

Restricted education is unavailable unless the actual current pause calls for the existing reviewed `clinical_pause` template, generated by the pure shared preparer using original meal facts and no official-day input. Old education cannot bypass a current restriction. Under unrestricted policy, the persisted educational text is identified as the original comment at registration. No LLM or legacy professional persona is invoked.

Real producer combinations include n10/reduced-intake pause without hide flags, professional-diet protein hide plus pause, no-plan/absent-phase all-field hiding, and incomplete assessment without pause. Independently fabricated calorie-only/objective-only/block-only policies are not passed off as real current sources in tests. The implementation still handles each public hide flag explicitly.

V1's `lines[].text`, `food_comment` and `incentive` are opaque; regex redaction cannot prove them safe. Any restriction, incomplete or unavailable policy prevents their display. Unknown/drifting policy withholds the entire wrapper; only a known stable restricted policy can produce the neutral legacy placeholder.

## Qualification and activation

Tests use actual state decoding/public projection and controlled backend source/receipt doubles, including the real default RPC factories. They cover unrestricted six sections, historical counters after current body changes, current pause/hide/incomplete, legacy restrictions, epoch/reset/drift/ownership/log failures, callback/input mutation and outages. No PG, cloud, provider, native or domain effects are performed.

Root must qualify the complete driver with actual SDK/REST/current observations and preserve this wrapper boundary before any public route/native activation. The original feedback service remains a separate immutable historical surface and must not be directly exposed as current clinical presentation. This increment does not activate a route, capability or native reader.
